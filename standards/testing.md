# Стандарти тестування

## Рівні тестів

| Рівень          | Де                     | Що перевіряє                                                                                        | Залежності          |
| --------------- | ---------------------- | --------------------------------------------------------------------------------------------------- | ------------------- |
| Unit            | `test/unit/`           | DI-контейнер, валідацію, пагінацію, сервіси (бізнес-правила spec) на in-memory репозиторіях         | немає               |
| Інтеграційні    | `test/integration/`    | Контракт репозиторіїв (memory і PostgreSQL поводяться однаково), CHECK-обмеження, seed, атомарність | PostgreSQL          |
| E2E             | `test/e2e/`            | Сценарії spec через HTTP: коди 401/403/404/409/422, soft delete, пагінація, `bpId` у логах          | memory і PostgreSQL |
| Мутаційні (код) | `stryker.config.json`  | Що тести справді ловлять зміни в коді, а не лише виконують його                                     | немає               |
| Мутаційні (SQL) | `test/sql-mutants.tsv` | Що кожна бізнес-умова в SQL має тест, який падає без неї                                            | PostgreSQL          |

## Критерії

1. **Кожне правило spec має тест.** У назві тесту — розділ spec (`spec §4`), щоб на захисті було видно, що чим перевірено.
2. **Тести з БД обов'язкові.** `npm test` і CI запускають усе на PostgreSQL; без доступної БД прогін **падає**, а не пропускає тести мовчки. Без БД — лише явно: `npm run test:nodb`, `npm run test:unit`, `make mutation`.
3. **Mutation score ≥ 80 %** (поріг `break` у Stryker; ціль — 90 %+). Поточний результат — 100 %.
4. **Еквівалентні мутанти** (зміна, яка не змінює поведінку) спершу прибираються спрощенням коду. Лише якщо це неможливо — коментар `// Stryker disable next-line <Mutator>: <чому еквівалентний>`.
5. **SQL-умови** (`WHERE`, `ORDER BY`, `LIMIT/OFFSET`, `FOR SHARE`) Stryker не мутує. Кожна з них записана в `test/sql-mutants.tsv`; `make mutation-sql` має вбивати 100 %. Нова умова в SQL → новий рядок у цьому файлі.
6. **Одна поведінка — одне джерело правди.** In-memory і PostgreSQL репозиторії проходять один і той самий контрактний тест.
7. **Логи — частина поведінки.** Бізнес-події (`entry created`, `note created`, …) і `bpId` перевіряються тестами.
8. Unit-тести запускаються в pre-commit hook (≈2 с).

## Команди

```bash
make db-up          # PostgreSQL у Docker (потрібен для make test і make mutation-sql)
make test           # усі тести
make test-nodb      # без БД
make coverage       # покриття: підсумок у консолі й reports/coverage/
make mutation       # Stryker → reports/index.html
make mutation-sql   # ручні мутанти SQL
make report         # усе разом → reports/index.html (звіт якості для захисту)
```
